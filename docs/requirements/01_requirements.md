# 要件定義書

## 1. プロジェクト概要

- **プロジェクト名**: IT Learning Navigator（仮）
- **概要**: AIへの質問回答の中でわからない単語をハイライトすることで、ユーザーの理解レベルを分析し、学習すべき内容をアドバイスするWebアプリ
- **解決する課題**: IT業界の駆け出しが「何を学べばよいか分からない」「自分の知識の穴がどこにあるか分からない」という状態を解消する
- **ターゲットユーザー**: IT業界に入ったばかりで、知識の全貌がまだ見えていない駆け出しエンジニア・ITワーカー

---

## 2. 機能要件（ユーザーストーリー）

### Must（必須）

- [ ] **US-001**: 駆け出しITワーカーとして、AIに技術的な質問を入力したい。なぜなら分からないことをすぐに調べたいから
- [ ] **US-002**: 駆け出しITワーカーとして、AIの回答文中でわからない単語をハイライト（選択）したい。なぜなら理解できなかった箇所を記録したいから
- [ ] **US-003**: 駆け出しITワーカーとして、ハイライトしたワードを確認してから「OK」ボタンで送信したい。なぜなら誤選択を修正できるようにしたいから
- [ ] **US-004**: 駆け出しITワーカーとして、ハイライトしたワード群から「自分の理解レベル（どの水準にいるか）」を分析してほしい。なぜなら自分の立ち位置を客観的に把握したいから
- [ ] **US-005**: 駆け出しITワーカーとして、「次に何を学べばよいか」の具体的なアドバイスをテキストで受け取りたい。なぜなら学習の優先順位を決めたいから

### Should（重要）

- [ ] **US-010**: 駆け出しITワーカーとして、ハイライトした単語の一覧を分析結果と一緒に確認したい。なぜなら何が理解できていなかったかを振り返りたいから
- [ ] **US-011**: 駆け出しITワーカーとして、分析結果で「ITのどの領域（ネットワーク・セキュリティ・開発等）の知識が不足しているか」を把握したい。なぜなら自分の弱い分野を認識したいから

### Could（あれば嬉しい）

- [ ] **US-020**: 駆け出しITワーカーとして、過去の質問・分析履歴を保存・参照したい。なぜなら学習の進捗を継続的に追いたいから
- [ ] **US-021**: 駆け出しITワーカーとして、学習アドバイスをロードマップ形式で視覚的に確認したい。なぜなら全体の学習ステップを把握したいから
- [ ] **US-022**: 駆け出しITワーカーとして、よく引っかかる用語のランキングを見たい。なぜなら自分のつまずきパターンを把握したいから

### Won't（今回は対象外）

- **US-030**: ユーザーアカウント登録・ログイン機能（MVPはセッション完結）
- **US-031**: 他ユーザーとの比較・ランキング機能
- **US-032**: 学習コンテンツ（動画・記事）の提供

---

## 3. 非機能要件

- **パフォーマンス**: AI回答は5秒以内に返す。分析・アドバイス生成は3秒以内
- **セキュリティ**: APIキーはサーバーサイドで管理。ユーザーの質問内容は外部に保存しない（MVPフェーズ）
- **可用性**: MVP段階では特定のSLA不要。開発・検証用途
- **スケーラビリティ**: MVP後の履歴保存・ユーザー管理追加を想定した拡張可能な設計
- **保守性**: コンポーネント単位での機能追加がしやすい構成

---

## 4. 制約条件

- **技術的制約**: AIはClaude API（Anthropic）またはOpenAI APIを使用（外部サービス依存）
- **スケジュール制約**: 特になし（MVP優先）
- **予算制約**: AI APIの利用コストを最小化する設計（不要なリクエストを削減）

---

## 5. 用語定義

| 用語 | 定義 |
|------|------|
| ハイライト | AIの回答文中でユーザーが理解できなかった単語・フレーズをテキスト選択すること |
| 理解レベル | ハイライトされた単語の領域・難易度から推定する、ユーザーのIT知識の習熟度 |
| 立ち位置 | IT知識の習熟度マップ上でのユーザーの現在地（例：「ネットワーク基礎は理解、セキュリティは未入門」等） |
| 学習アドバイス | 理解レベル分析に基づいて提示する「次に学ぶべきトピック・分野」の提案 |
| MVP | Minimum Viable Product。最小限の機能で動作する初期バージョン |
